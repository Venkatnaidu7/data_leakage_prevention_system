# DLP Policy Engine Guide

## 1. Overview

The DLP Policy Engine evaluates findings generated by the detection pipeline against a set of prioritized, versioned rules. Based on matched criteria, the engine determines the appropriate security action and severity.

## 2. Policy Schema

Each policy is defined by the following attributes:

- **ID & Name:** Unique identifier and human-readable descriptive title.
- **Description:** Context on why this policy exists (e.g., regulatory compliance, secret hygiene).
- **Enabled (`bool`):** Whether the policy is active during live scans.
- **Priority (`int`):** Evaluation order. Lower integers indicate higher priority (e.g., priority `1` takes precedence over priority `10`).
- **Target Detectors (`list[str]`):** List of detector types this policy monitors (e.g. `["credit_card", "secret_key"]` or `["*"]` for any).
- **Match Threshold (`int`):** Minimum count of findings required to trigger the policy (default: `1`).
- **Action:**
  - `LOG`: Quietly record the finding in the database and audit trail without raising an operational alert.
  - `WARN`: Flag the event as an advisory warning.
  - `BLOCK`: Signal that the transaction/file transfer must be halted at integrated enforcement points.
  - `QUARANTINE`: Move the payload or reference into restricted isolation for compliance review.
  - `ESCALATE`: Automatically create a high-priority incident and notify security analysts.
- **Severity:** `LOW`, `MEDIUM`, `HIGH`, `CRITICAL`.
- **Dry-Run / Simulation Mode (`bool`):** When enabled on a policy or requested via API, the engine simulates what action *would* have been taken without mutating incident state.

## 3. Conflict Resolution Order

When multiple policies match findings within a single scan request, conflicts are resolved deterministically:

1. **Active Status:** Disabled policies are skipped.
2. **Priority Rank:** Lower numerical priority value wins (Priority `1` > Priority `2`).
3. **Severity Weight:** If priorities are identical, the higher severity action wins:
   `CRITICAL` > `HIGH` > `MEDIUM` > `LOW`.
4. **Action Weight:** If severity is also identical, the most restrictive action takes precedence:
   `BLOCK` > `QUARANTINE` > `ESCALATE` > `WARN` > `LOG`.

## 4. Policy Simulation Mode

Simulation mode allows security analysts and policy authors to test new rule sets against historical or synthetic test payloads. The engine produces an evaluation report containing:
- Matched detector findings.
- Policies triggered.
- Selected winning policy.
- Action rationale and explanation.
- Indication that no live incidents or blocks were triggered.

## 5. Built-in Baseline Policies

1. **PCI-DSS Cardholder Data Protection:**
   - Detectors: `credit_card`
   - Threshold: 1
   - Action: `BLOCK`
   - Severity: `CRITICAL`
2. **High-Entropy Secrets & API Keys:**
   - Detectors: `secret_key`
   - Threshold: 1
   - Action: `BLOCK`
   - Severity: `CRITICAL`
3. **Bulk PII Leakage Alert:**
   - Detectors: `email`, `phone`
   - Threshold: 5
   - Action: `ESCALATE`
   - Severity: `HIGH`
4. **General PII Monitoring:**
   - Detectors: `email`, `phone`
   - Threshold: 1
   - Action: `LOG`
   - Severity: `LOW`
